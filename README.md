# Simultaneous

**플레이: https://jungjungtaemin.github.io/overJanggi/**

동시 턴제 전략 점령 게임. 두 플레이어가 각자 5기물의 행동을 **동시에** 계획하고, 한꺼번에 공개해
정해진 5단계 순서로 결과를 계산한다. 오버워치식 역할 분담(탱커/딜러/지원) + 장기식 기물 운용 +
중앙 점령지 쟁탈.

React 18 + TypeScript(strict) + Vite 5 + Zustand 4 + Vitest 2.

## 게임 규칙 요약

- 기물 10종(탱커 3 · 딜러 4 · 지원 3) 중 **중복 허용 5기물**을 드래프트하고 자기 시작지점에 배치한다.
- 매 턴 기물마다 이동 / 공격 / 기술 / 대기를 고른다. 양쪽 계획은 동시에 공개된다.
- 턴 해결은 항상 **이동 → 공격 전 상태변화(방벽·구속·공격모드) → 공격 → 회복 → 턴종료** 순서.
  각 단계 안에서는 이동력 → 공격력 → 역할 순의 우선순위가 높은 기물부터 하나씩 완전히 행동한다.
- **다수결 점령**: 중앙 점령지의 생존 기물을 팀별로 세어, **인원이 많은 쪽이 1점**을 얻는다.
  정확히 동수면 양 팀 모두 0점. 몇 명 차이인지는 무관해서 3:1도 5:1도 똑같이 1점이고,
  **턴당 최대 1점**이 상한이다. 포탑은 소환물이라 세지 않는다.
- **10점 선도달 즉시 승리.** 사망한 기물은 2턴 뒤 시작지점에서 완전 회복해 부활한다.

## 플레이 모드

| 모드 | 설명 |
|---|---|
| 로컬 대전 | 한 화면에서 한 사람이 양 진영을 모두 조작한다(디버그·학습용). |
| AI 대전 | 휴리스틱 AI와 대전. 쉬움 / 보통 / 어려움 3난이도. |
| 온라인 대전 | PeerJS(WebRTC) P2P. 방 코드 6자리를 상대에게 알려주면 접속된다. |

### 온라인 대전 사용법

1. 한 사람이 **방 만들기**를 누르면 `ABC123` 같은 6자리 방 코드가 뜬다(클릭하면 클립보드 복사).
2. 상대가 그 코드를 입력하고 **참가**를 누르면 연결된다. 방장이 Player 1, 참가자가 Player 2.
3. 연결 뒤에는 각자 자기 진영의 드래프트 · 배치 · 매 턴 계획만 조작한다.

서버 없이 브라우저끼리 직접 연결되며, 중계는 PeerJS 공개 시그널링 서버만 사용한다.
게임 상태는 **방장 권위(host-authoritative)** 로 처리한다 — 참가자의 조작은 방장에게 전달되고,
방장이 적용한 뒤 전체 상태를 되돌려 보낸다. 이 게임은 설계상 숨겨진 정보가 없어(양쪽 계획을
동시에 공개하는 방식) 상태를 통째로 공유해도 규칙상 손해가 없고, 대신 무작위 요소가 한쪽에서만
굴러가 양쪽 화면이 갈라지는 문제를 구조적으로 막을 수 있다.

### AI 난이도

난이도는 "얼마나 깊이 읽는가"가 아니라 **"어떤 실수를 얼마나 자주 하는가"** 로 구현했다.
셋 다 같은 평가 함수를 쓰고, 잡음(noise) · 기술 사용 여부 · 점령지/위협/처치 가중치만 다르다.

- **쉬움** — 기술을 전혀 쓰지 않고 눈앞의 적에게 반응만 한다. 자주 실수한다.
- **보통** — 기술을 쓰고 점령지를 노린다. 가끔 손해 보는 수를 둔다.
- **어려움** — 점령지를 우선하고, 사거리 밖에서 접근하며, 마무리를 놓치지 않는다.

AI는 트리 탐색을 하지 않는다. 동시 턴 게임이라 상대 계획을 알 수 없어 미니맥스의 이득이 작고,
후보 수가 기물 5개 × (방향 × 거리 × 기술 조합)으로 폭발하기 때문이다. 대신 기물별로 후보 계획을
만들어 한 수 평가하고, 협동은 공통 목표 항(점령지 거리·적 위치)을 통해 간접적으로 나온다.
모든 후보는 엔진의 `isActionLegal`을 통과해야만 채택되므로 AI가 불법 계획을 낼 수 없다.

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # Vitest (엔진 + AI)
npm run build    # tsc -b && vite build
npm run preview  # 빌드 결과 미리보기
```

게임 로직은 프레임워크에 의존하지 않는 순수 함수(`src/engine/*.ts`)이고 Zustand 스토어는
얇은 래퍼다. 그래서 엔진은 React 없이 단독으로 테스트된다.

```
src/
  data/         unitTypes.ts(기물 10종 스탯), mapDefinitions.ts(정원 맵), constants.ts
  engine/       resolveTurn.ts(5단계 오케스트레이터), resolvers/*, targeting.ts, grid.ts, validation.ts, rng.ts
  ai/           aiPlayer.ts(휴리스틱 계획 생성), difficulty.ts(난이도 프로필)
  online/       netBridge.ts(PeerJS 방 생성/참가, 스냅샷 동기화)
  store/        gameStore.ts
  components/   Menu, Board, Planning, Hud, Log, DraftSetup
  test/         engine/*.test.ts, ai/*.test.ts
```

## 배포

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 테스트 → 빌드 → GitHub Pages 배포를
자동으로 수행한다. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 설정해야 한다.
Vite `base`는 `'./'`(상대 경로)라 저장소 이름과 무관하게 동작한다.

구현 이력과 설계 판단은 [PROGRESS.md](./PROGRESS.md) 참고.
