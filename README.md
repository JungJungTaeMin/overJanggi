# Simultaneous

**플레이: https://jungjungtaemin.github.io/overJanggi/**

동시 턴제 전략 점령 게임. 두 플레이어가 각자 5기물의 행동을 **동시에** 계획하고, 한꺼번에 공개해
정해진 5단계 순서로 결과를 계산한다. 오버워치식 역할 분담(탱커/딜러/지원) + 장기식 기물 운용 +
중앙 점령지 쟁탈.

React 18 + TypeScript(strict) + Vite 5 + Zustand 4 + Vitest 2.

## 게임 규칙 요약

- 기물 10종(탱커 3 · 딜러 4 · 지원 3) 중 **중복 허용 5기물**을 드래프트하고 자기 시작지점에 배치한다.
- 매 턴 기물마다 이동 / 공격 / 기술 / 대기를 고른다. 양쪽 계획은 동시에 공개된다.
- 턴 해결은 항상 **이동 → 공격 전 상태변화(방벽·구속·공격모드) → 공격 → 회복 → 턴종료** 순서.
  각 단계 안에서는 이동력 → 공격력 → 역할 순의 우선순위가 높은 기물부터 하나씩 완전히 행동한다.
- **인원 차 점령**: 중앙 점령지의 생존 기물을 팀별로 세어, 상대보다 **2명 이상** 많은 쪽이 1점을 얻는다.
  상대가 점령지에 아예 없으면 **한 명만으로도** 1점. 즉 1:0은 득점이지만 2:1은 경합이라 0점이다.
  몇 명 차이인지는 무관해서 3:1도 5:1도 똑같이 1점이고, **턴당 최대 1점**이 상한이다.
  포탑은 소환물이라 세지 않는다.
- **15점 선도달 즉시 승리** (평균 판당 35~40턴 안팎). 사망한 기물은 3턴 뒤 시작지점에서 완전 회복해 부활한다.

규칙을 처음 본다면 화면 오른쪽 위 **「게임 방법」**을 누르면 된다. 승리 조건, 한 턴의 5단계,
점령 점수 예시, 기물 10종의 이동·공격·회복 사정권을 그림으로 보여준다. 대전 중에도 열 수 있고,
그림에 쓰인 사정권은 실제 판을 굴리는 엔진 함수로 계산한 것이라 밸런스가 바뀌면 그림도 같이 바뀐다.

### 해결 과정 보기

공개 버튼을 누르면 결과가 한 번에 튀지 않고 **위 순서 그대로 한 단계씩 재생된다**. 판 위에는 그
단계에 실제로 벌어진 일이 표시로 남는다 — `-8` 피해, `+3` 회복, `막힘`(방벽이 먹음),
`빗나감`(사거리 안에 아무도 없었음), `격추`, `부활`. 화살선이 누가 누구에게 한 짓인지 잇는다.

**`막힘`과 `빗나감`은 다른 사건이다.** 둘 다 체력이 0만큼 변하지만, 앞은 상대가 방벽을 썼다는
뜻이고 뒤는 조준이 비었다는 뜻이라 다음 수가 정반대다. 그래서 표시는 체력 차이가 아니라 해결
로그의 실제 사건에서만 만든다.

재생 바에서 단계를 클릭하면 그 지점에 멈춰 볼 수 있고, **건너뛰기**로 바로 결과만 볼 수도 있다.
**「단계별 재생」 체크를 끄면** 예전처럼 결과만 뜬다(설정은 브라우저에 기억된다). 아무 일도 없던
단계는 저절로 접히므로 조용한 턴은 짧게 지나간다. 온라인에서는 양쪽이 **각자 속도로** 본다 —
상대가 건너뛰어도 내 재생은 그대로다.

### 쏘기 전에 무엇이 맞는지 보기

주황색 칸은 **사선이 뻗는 범위**일 뿐, 「여기 쏘면 맞는다」는 뜻이 아니다. 그래서 공격 방향을
지정하는 동안 판 위에 **조준 표식**이 함께 뜬다.

| 표식 | 뜻 | 다음 수 |
|---|---|---|
| 주황 조준선 + `−8` | 이 방향으로 쏘면 맞는다(예상 피해) | 그대로 쏜다 |
| 하늘색 조준선 | 방벽에 막힌다 | 방벽부터 걷어낸다 |
| 회색 조준선 | 아군이 사선에 서 있다 | 그 아군을 비키게 한다 |
| (표식 없음) | 그 방향에는 아무도 없다 | 조준을 옮긴다 |

예상 피해는 측면 교란 같은 보너스까지 더한 값이고, **해결 단계가 쓰는 바로 그 판정 함수**로
계산한다 — 미리보기와 실제 결과가 갈라질 수 없다. 다만 동전으로 사거리가 갈리는 기물(지원 3)은
계획 시점에 결과를 알 수 없으므로 앞면 기준 상한으로 그린다.

「공개 및 해결」 옆의 `n/5 지정`은 이번 턴 행동을 잡은 기물 수다. **「대기」도 선택이므로 막지는
않고** 세기만 한다 — 하나도 안 잡은 채 넘기려 할 때만 주황으로 뜬다.

## 조작

클릭을 최대한 아끼도록 짜여 있다. 아래는 전부 **지름길**이고, 하나하나 손으로 고르는 길은 그대로 있다.

| 하고 싶은 것 | 클릭 |
|---|---|
| 판 시작 | 시작 화면의 **「클릭 한 번으로 시작」** — 추천 편성 + 자동 배치로 AI전이 바로 열린다. |
| 드래프트 | **「추천 편성」** 한 번이면 5기물이 편성 규칙에 맞게 채워진다. |
| 배치 | **「자동 배치」** — 손으로 이미 놓은 기물은 그대로 두고 빈 자리만 채운다. |
| 이동 | 갈 칸을 클릭. 그 기물의 계획이 끝나면 **다음 기물이 저절로 선택**되므로, 한 턴에 칸 5번만 찍으면 된다. |
| 공격 | 사거리 안의 **적을 클릭**하면 이동 지정 모드여도 공격으로 잡힌다(빈 칸 조준은 클릭 모드 전환 필요). |
| 턴 넘기기 | **Space** 또는 **Enter**. |

한 기물이 이동을 여러 번 얻는 경우(시간 역행형 등)에는 남은 이동 구간을 다 찍을 때까지 넘어가지 않는다.
돌진·기동형의 돌진은 적을 밟고 지나가는 기술이라, 계획 중일 때 적 칸 클릭이 공격이 아닌 이동으로 잡힌다.

## 플레이 모드

| 모드 | 설명 |
|---|---|
| 로컬 대전 | 한 화면에서 한 사람이 양 진영을 모두 조작한다(디버그·학습용). |
| AI 대전 | 휴리스틱 AI와 대전. 쉬움 / 보통 / 어려움 3난이도. |
| 온라인 대전 | PeerJS(WebRTC) P2P. 방 코드 6자리를 상대에게 알려주면 접속된다. |

### 편성 규칙

맵과 함께 시작 화면에서 고른다. 세 모드 모두에 적용되고, **기물 스탯은 규칙과 무관하게 같다** —
바뀌는 건 드래프트에서 무엇을 고를 수 있는가뿐이다.

| 규칙 | 내용 |
|---|---|
| 자유 편성(기본) | 10종에서 제약 없이 5기물. 같은 기물을 여러 기 넣어도 된다. |
| 탱커 1명 고정 | 탱커는 정확히 1기, 나머지 4기는 딜러·지원에서. |

규칙이 기물의 값어치를 실제로 바꾼다는 게 이 모드를 둔 이유다. 밸런스 측정(1000판, 두 맵)에서
탱커 3종의 반응이 서로 반대였다 — 방어 강화형은 **혼자일 때** 값이 나오고(자기가 유일한 전선),
돌진·기동형은 **짝이 있을 때** 값이 나온다(파고드는 동안 뒤를 받쳐 줄 몸이 필요). 탱커를 하나로
묶으면 앞에서 겹겹이 버티는 편성이 사라져 교전이 빨라지는 대신, 기물 간 승점 편차는 오히려
벌어진다(정원 맵 15.2%p → 19.0%p).

규칙은 `src/data/rosterRules.ts` 한 곳에만 적혀 있고 드래프트 화면 · AI 편성 · 밸런스 시뮬레이터가
모두 그 파일을 근거로 삼는다. 온라인 대전에서는 맵과 마찬가지로 **호스트가 고른 규칙**으로 진행된다.

### 온라인 대전 사용법

1. 한 사람이 **방 만들기**를 누르면 `ABC123` 같은 6자리 방 코드가 뜬다(클릭하면 클립보드 복사).
2. 상대가 그 코드를 입력하고 **참가**를 누르면 연결된다. 방장이 Player 1, 참가자가 Player 2.
3. 연결 뒤에는 각자 자기 진영의 드래프트 · 배치 · 매 턴 계획만 조작한다.

**온라인에서는 판을 각자 자기 쪽에서 본다** — 내 진영이 언제나 아래, 상대가 위다. 두 화면은
서로 180° 돌아간 그림이고(상하 거울이 아니라 회전이라, 한쪽의 왼쪽 골목이 반대쪽에는 오른쪽으로
보인다 — 마주 앉아 판을 돌려 놓은 것과 같다) 엔진 좌표는 하나뿐이라 규칙·AI·통신은 시점을 모른다.

**온라인에서는 상대의 미공개 정보를 가린다.** 드래프트 중 상대 편성, 배치 화면의 상대 진형,
그리고 공개 전 상대의 이번 턴 이동 계획이 안 보인다. 감추지 않는 건 **이미 공개된 것** —
해결이 끝난 판 위 위치·체력·쿨타임·로그다. 이건 양쪽이 함께 본 결과라 감추면 다음 수를 세울
근거가 사라진다. 로컬·AI 대전은 그대로 다 보인다(로컬은 한 사람이 양쪽을 조종하고, AI는 사람
화면을 보고 두지 않는다).

서버 없이 브라우저끼리 직접 연결되며, 중계는 PeerJS 공개 시그널링 서버만 사용한다.
게임 상태는 **방장 권위(host-authoritative)** 로 처리한다 — 참가자의 조작은 방장에게 전달되고,
방장이 적용한 뒤 전체 상태를 되돌려 보낸다. 무작위 요소가 한쪽에서만 굴러가 양쪽 화면이 갈라지는
문제를 구조적으로 막을 수 있다.

> **가림은 화면까지다.** 방장 권위 구조라 방장 브라우저에는 참가자의 계획이 그대로 들어 있고,
> 참가자에게도 전체 스냅샷이 그대로 간다. 개발자 도구를 열면 볼 수 있다는 뜻이다. 규칙 수준에서
> 막으려면 계획을 해시로 먼저 보내고 나중에 원본을 까는 커밋-공개 방식이 필요한데, 그건 통신
> 계층을 다시 짜는 일이라 하지 않았다. 서로 믿고 두는 상대와의 대전을 전제로 한다.

### AI 난이도

난이도는 "얼마나 깊이 읽는가"가 아니라 **"어떤 실수를 얼마나 자주 하는가"** 로 구현했다.
셋 다 같은 평가 함수를 쓰고, 잡음(noise) · 기술 사용 여부 · 점령지/위협/처치 가중치만 다르다.

- **쉬움** — 기술을 전혀 쓰지 않고 눈앞의 적에게 반응만 한다. 자주 실수한다.
- **보통** — 기술을 쓰고 점령지를 노린다. 가끔 손해 보는 수를 둔다.
- **어려움** — 점령지를 우선하고, 사거리 밖에서 접근하며, 마무리를 놓치지 않는다.

AI는 트리 탐색을 하지 않는다. 동시 턴 게임이라 상대 계획을 알 수 없어 미니맥스의 이득이 작고,
후보 수가 기물 5개 × (방향 × 거리 × 기술 조합)으로 폭발하기 때문이다. 대신 기물별로 후보 계획을
만들어 한 수 평가하고, 협동은 공통 목표 항(점령지 거리·적 위치)을 통해 간접적으로 나온다.
모든 후보는 엔진의 `isActionLegal`을 통과해야만 채택되므로 AI가 불법 계획을 낼 수 없다.

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # Vitest (엔진 + AI)
npm run build    # tsc -b && vite build
npm run preview  # 빌드 결과 미리보기
```

게임 로직은 프레임워크에 의존하지 않는 순수 함수(`src/engine/*.ts`)이고 Zustand 스토어는
얇은 래퍼다. 그래서 엔진은 React 없이 단독으로 테스트된다.

```
src/
  data/         unitTypes.ts(기물 10종 스탯), mapDefinitions.ts(정원 맵), constants.ts
  engine/       resolveTurn.ts(5단계 오케스트레이터), resolvers/*, targeting.ts, grid.ts, validation.ts, rng.ts
                replay.ts(단계별 재생 기록 — resolveTurn에 선택 인자로 붙어, 안 쓰면 비용 0)
                aim.ts(이 방향으로 쏘면 무엇이 맞는가 — 해결기와 조준 미리보기가 함께 쓴다)
  ai/           aiPlayer.ts(휴리스틱 계획 생성), difficulty.ts(난이도 프로필)
  online/       netBridge.ts(PeerJS 방 생성/참가, 스냅샷 동기화)
  store/        gameStore.ts
  components/   Menu, Board, Planning, Hud, Log, DraftSetup
  test/         engine/*.test.ts, ai/*.test.ts
```

## 배포

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 테스트 → 빌드 → GitHub Pages 배포를
자동으로 수행한다. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 설정해야 한다.
Vite `base`는 `'./'`(상대 경로)라 저장소 이름과 무관하게 동작한다.

구현 이력과 설계 판단은 [PROGRESS.md](./PROGRESS.md) 참고.
